# Monthly updates

Once a month we write down what changed in HisaabSaathi, what we learned, and what comes next,
in plain words. One file per month: `YYYY-MM.md`.

## How to write one

Copy the outline below into a new file for the month and fill it in. Keep it short: a page or two.

- **Only numbers we can stand behind.** Use what the app's opt-in weekly counts, partners' dispute
  logs, downloads and test results show. Where we don't know a number, say so.
- **Nothing about a person.** No names, quotes or photos of workers unless they agreed in writing.
  Dispute results only as totals across partners ([`../partners/dispute-log.md`](../partners/dispute-log.md)).
- **Say what went wrong too.** Bugs we shipped, things workers found hard, and what we changed.

```markdown
# HisaabSaathi: <Month YYYY>

## In one paragraph

## What changed in the app
(releases, with the version numbers and download link)

## How it is used
(from the opt-in weekly counts: phones, entries saved, how often the app got an entry wrong, by
week; and downloads)

## Disputes
(from partners' logs: cases, settled, rupees recovered, which records helped)

## What we learned
(from workers, partners and tests)

## Data and models
(wage data checked or updated, model or speech changes, test results)

## Next month
```
